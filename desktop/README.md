# Storybook Studio

Локальное Linux-приложение для визуальных проверок Storybook. Несколько проектов, эталоны, история прогонов, сравнение изображений, наложение, подтверждение и отклонение изменений. Работает с папкой исходников, готовой сборкой или URL, без облачного аккаунта.

В приложении нет встроенных конфигураций конкретных проектов, списков их историй, API-моков или исправлений компонентов. Съёмка выполняется исправленным Loki в закреплённом Chrome/Docker; изображения сравнивает pixelmatch. Новые и изменённые снимки принимаются только вручную.

## Запуск

Требования: Linux x64, Node.js 22.12+ (проверено с 24), pnpm 9, Docker с доступом текущего пользователя. Для режима сборки нужны установленные зависимости исходного проекта и его менеджер пакетов.

```sh
pnpm install --frozen-lockfile
pnpm start
```

Если система не поддерживает песочницу Electron, используйте `pnpm start --no-sandbox`. Это отключает защиту песочницы Chromium; Node.js в интерфейсе остаётся выключенным, но это не заменяет системную песочницу. Содержимое Storybook загружается в отдельном Chrome в Docker, а не в интерфейсе Electron.

```sh
pnpm run package
node scripts/install.cjs
```

Упаковка создаёт `dist/StorybookStudio-linux-x64`; установка копирует программу в `~/Applications/StorybookStudio` и добавляет **Storybook Studio** в меню приложений. Launcher запоминает путь к Node.js, чтобы менеджер пакетов был доступен при запуске из меню. По умолчанию песочница включена. Для систем, где она не работает: `STUDIO_NO_SANDBOX=1 node scripts/install.cjs`.

## Подключение проекта

Нажмите **+** и выберите источник:

- **Папка проекта**: укажите исходники, менеджер пакетов, имя скрипта сборки, например `build-storybook`, и выходную папку, обычно `storybook-static`. Сборка выполняется во временной копии, исходники не изменяются. Корневой `node_modules` подключается из исходного проекта; зависимости автоматически не устанавливаются.
- **Готовая папка**: каталог с `iframe.html` и `index.json`.
- **URL**: адрес запущенного или опубликованного Storybook, включая подпуть, например `http://localhost:6006` или `https://example.org/components/`. URL должен быть доступен Docker-браузеру. Сессия авторизации из обычного браузера не переносится.

Задайте размер окна и, при необходимости, регулярное выражение для фильтрации названий историй. Для обычного Storybook внешний конфиг не требуется.

Результаты появляются во время прогона. Откройте карточку для сравнения рядом, diff или наложения. **Подтвердить** обновляет эталон; **Отклонить** сохраняет прежний эталон. Отсутствующие истории удаляются из эталонов только после подтверждения. Фильтрация и пропуск истории не считаются её удалением. Эталоны на момент каждого прогона сохраняются отдельно: последующие подтверждения не переписывают историю.

## Как определяется готовность

Приложение ждёт завершения рендера, loaders и `play` в Storybook, шрифтов и изображений. Ошибки рендера и `play` дают результат «Ошибка», а не новый эталон. По умолчанию ожидаются сетевые ресурсы страницы: документы, JavaScript, стили, изображения и шрифты. Постоянные API-запросы, polling и намеренные состояния загрузки не требуют списка исключений по ID историй.

Это не означает, что приложение может угадать готовность любого бизнес-интерфейса. Если данные загружаются после рендера и нужно снять результат запроса, задайте `readySelector`, используйте ожидание в `play`/loader или явно включите `network: 'all'`. Общее ожидание отсутствия запросов может никогда не закончиться при polling или бесконечной загрузке; это также отмечено в [документации Playwright](https://playwright.dev/docs/api/class-page#page-wait-for-load-state).

Моки, авторизация, шрифты и детерминированные данные относятся к Storybook самого проекта. Приложение не заменяет ответы API, дату, случайные значения и изображения автоматически. CSS/JS-анимации отключаются средствами Loki по умолчанию; это можно отключить в конфиге. Совместимость со всеми библиотеками анимаций не гарантируется.

## Необязательный конфиг

Выберите `.cjs` или `.json` файл в настройках проекта. Если поле пустое, для локального источника приложение ищет в его корне `storybook-studio.config.cjs`, затем `storybook-studio.config.json`. Для URL конфиг подключается только явно. Настройки перечитываются перед каждым запуском; опечатки и отсутствующий явно указанный файл вызывают ошибку.

```js
// storybook-studio.config.cjs
module.exports = {
  version: 1,
  concurrency: 4,
  threshold: 0,
  capture: {
    network: 'assets',
    timeoutMs: 60000,
    settleMs: 350,
    selector: 'body',
    readySelector: '',
    errorSelector: '',
    disableAnimations: true,
    failOnBrokenImages: true,
    allowMockHttpErrors: false,
    ignoreRequests: [],
    ignoreRequestFailures: [],
  },
};
```

- `network`: `assets`, `all` или `none`. `none` отключает ожидание сетевых событий; ожидание рендера, шрифтов и изображений сохраняется.
- `timeoutMs`: общий лимит подготовки снимка. `settleMs`: дополнительная пауза для эффектов после рендера.
- `selector`: область снимка. `readySelector`: CSS-маркер, появления которого нужно дождаться. `errorSelector`: CSS-маркер ошибки, наличие которого запрещает снимок.
- `allowMockHttpErrors`: разрешает HTTP-ошибки отслеживаемых ресурсов, возвращённые service worker, например для намеренной демонстрации заглушки. По умолчанию выключено.
- `ignoreRequests`: регулярные выражения для запросов, которые не нужно ждать. `ignoreRequestFailures`: разрешённые ошибки отслеживаемых запросов. Обычно оба списка пусты.
- `threshold`: чувствительность pixelmatch, 0–1; по умолчанию 0. Это порог различия цвета пикселя, не процент допустимых отличий изображения.

При необходимости можно добавить правила `stories`. `match` — регулярное выражение по ID истории; правила применяются по порядку. Это пользовательская настройка, приложение не содержит предустановленных правил.

```js
module.exports = {
  version: 1,
  stories: [
    { match: '^async-example--', capture: { readySelector: '[data-ready]' } },
    { match: '--manual-only$', skip: true },
  ],
};
```

Также поддерживается существующий `parameters.loki.skip`. Сами эталоны пропущенных историй сохраняются.

Для подготовки изолированной копии перед сборкой CJS-конфиг может экспортировать функцию:

```js
module.exports = {
  version: 1,
  async prepare({ workspace, source, run, log }) {
    log('Подготовка временной копии');
    // workspace — временная копия, source — исходники.
    // При необходимости выполните свой скрипт в workspace:
    await run('node', ['scripts/prepare-storybook.cjs']);
  },
};
```

`run(command, args)` выполняет команду без shell, в `workspace`, пишет вывод в журнал и участвует в отмене прогона. `prepare` работает только в режиме сборки. CJS-конфиг выполняет код с правами пользователя, как скрипт сборки: подключайте доверенные файлы. Сам hook может обращаться к любым файлам; он не является песочницей. JSON-конфиг не исполняет код.

## Совместимость и ограничения

Целевой формат — веб-Storybook с `index.json` и современным preview API. Проверки совместимости находятся в `tests/fixtures`: HTML + Storybook 9.1.0 и 10.6.1, Vue 3 и React + Storybook 8.5.8. Все эти примеры находятся в репозитории и собираются в CI. Реальные проверки включают `play`, намеренные ошибки, бесконечный fetch, пропуск историй, вложенный URL и повторное совпадение эталонов.

Это проверенная матрица, а не обещание поддержки каждой версии Storybook. React Native, старые сборки без `index.json`, Windows/macOS и сложные monorepo-схемы сборки пока не проверены. Можно использовать готовую сборку или URL, если изолированная сборка проекта не подходит. Приложение использует Chrome в Docker с Linux host networking; драйвер не зависит от React/Vue/HTML-компонентов, но совместимость preview API требует проверки при обновлении Storybook.

## Данные

Настройки, эталоны и история хранятся в `~/.local/share/storybook-studio` либо `$XDG_DATA_HOME/storybook-studio`. `STUDIO_DATA_DIR` задаёт отдельное хранилище. Кнопка **Открыть папку** показывает его в файловом менеджере. Переустановка программы не удаляет данные. История накапливается на диске; для резервной копии закройте приложение и скопируйте всё хранилище.

Не запускайте CLI и GUI одновременно с одним хранилищем. Проверка без GUI: `node scripts/run-project.cjs [projectId]`. Конфиг и параметры конкретного прогона фиксируются в его метаданных; решения о подтверждении сохраняются сразу.

## Разработка и проверки

```sh
pnpm test
pnpm test:ui
pnpm fixtures:build
pnpm test:integration
```

`test` проверяет хранение, решения, устаревшие результаты, конфиги и изоляцию подготовки. `test:ui` запускает настоящий Electron и Docker, проверяя галерею, diff, наложение, принятие/отклонение во время прогона, отмену и перезапуск. Для среды без дисплея: `xvfb-run -a pnpm test:ui`. `fixtures:build` устанавливает закреплённые зависимости тестовых Storybook и собирает их; `test:integration` снимает их настоящим Docker-браузером. Артефакты сохраняются в `artifacts/` и не попадают в репозиторий.

Chrome закреплён по digest в `src/runner.cjs`. Исправления Loki хранятся в `patches/` и устанавливаются через pnpm. В репозитории есть workflow GitHub Actions для этих проверок. Локальные пользовательские проекты и конфиги не нужны для сборки и тестов репозитория.
